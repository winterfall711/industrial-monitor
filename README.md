# 基于 Modbus TCP 的工业设备数据采集与异常监测系统

## 1. 项目简介

本项目使用 Python 搭建工业设备数据采集与异常监测原型，通过模拟设备运行参数、Modbus TCP 通信、CSV 数据存储和扭矩异常检测，构建一套完整的数据采集与分析流程。

项目模拟采集设备的温度、转速和扭矩数据，实现寄存器读取、历史数据记录、趋势可视化、连续超限检测及报警事件统计。

**项目类型：** 个人项目

**技术栈：** Python、PyModbus、Modbus TCP、pandas、Matplotlib、CSV

> 本项目目前使用模拟设备数据进行验证，尚未直接接入真实工业设备。

## 2. 项目功能

- **设备数据模拟：** 生成温度、转速、扭矩等设备运行参数。
- **工业通信：** 搭建 Modbus TCP 服务端与客户端，通过保持寄存器传递模拟设备数据。
- **数据采集：** 周期性读取寄存器，进行工程量换算并记录时间戳。
- **历史数据存储：** 将采集数据保存至 CSV 文件，便于后续分析。
- **趋势可视化：** 使用 Matplotlib 绘制扭矩变化曲线及平均值参考线。
- **异常检测：** 根据实验设定的扭矩阈值识别单点超限，并检测连续三次超限。
- **报警事件统计：** 对连续超限记录进行归并，统计事件起止时间、触发时间、超限采样点数、最大扭矩及持续时间，并输出 CSV 报告。

## 5. 通信与数据设计

服务端通过 Modbus TCP 提供模拟设备数据，当前本地测试配置如下：

| 参数 | 配置 |
|---|---|
| 通信协议 | Modbus TCP |
| 服务端地址 | 127.0.0.1 |
| TCP 端口 | 5020 |
| 起始寄存器地址 | 0 |
| 数据类型 | 16 位寄存器值 |

当前保持寄存器映射：

| 寄存器地址 | 参数 | 数据处理 |
|---|---|---|
| 0 | 温度 | 原始值 ÷ 100 |
| 1 | 转速 | 原始值直接读取 |
| 2 | 扭矩 | 原始值 ÷ 100 |

以上为当前模拟项目使用的寄存器映射，不代表真实设备的寄存器定义。

## 6. 数据处理流程

1. 通过设备模拟器生成运行参数。
2. 将参数转换为寄存器整数值。
3. 服务端周期性更新保持寄存器。
4. 客户端通过 Modbus TCP 读取寄存器。
5. 将原始数据还原为工程量并记录时间戳。
6. 将采集结果追加保存至 CSV 文件。
7. 读取历史数据，计算统计指标并绘制趋势图。
8. 根据设定阈值识别超限记录，并归并连续超限事件。
9. 输出报警事件统计报告。

## 7. 异常检测逻辑

当前版本使用扭矩阈值进行基础异常检测。

- 单点检测：识别扭矩超过实验阈值的采样点。
- 连续检测：连续三次采样超限时触发报警。
- 事件归并：将连续超限记录归并为独立事件。
- 事件统计：记录开始时间、触发时间、结束时间、采样点数量、最大扭矩和持续时间。

当前模拟实验阈值为 34.5 N·m，连续采样间隔规则暂定为不超过 3 秒。

这些参数用于验证程序逻辑，并非真实设备的安全或质量标准。实际部署前需要依据设备规范与工艺要求重新确定。

## 8. 环境配置与运行

### 安装依赖

在项目对应的 Python 虚拟环境中执行：

```bash
python -m pip install pymodbus pandas matplotlib
```

如果依赖已经安装且程序能够正常运行，无需重复安装。

### 运行步骤

**第一步：启动设备模拟与通信服务端**

运行 `modbus_server.py`，启动服务端并持续更新寄存器。

**第二步：启动数据采集客户端**

运行 `modbus_client.py`，连接本地服务端并持续采集数据。

**第三步：分析历史数据**

运行 `analyze_data.py`，生成扭矩趋势图、异常检测结果及报警事件报告。

首次运行前，确保已经采集到有效数据，且 CSV 文件路径正确。

## 10. 当前限制与后续计划

当前项目仍属于基础原型，主要限制包括：

- 使用模拟数据，尚未验证真实生产设备上的检测效果。
- 当前采用固定阈值，尚未建立基于实际工艺数据的报警标准。
- 暂未实现完整的实时监控界面。
- 尚未建立真实废料记录与设备参数之间的关联分析。
- 通信断开、数据缺失等异常工况仍有进一步测试和完善的空间。

后续计划：

1. 完善通信异常处理与数据完整性检查。
2. 开展温度、转速、扭矩之间的相关性分析。
3. 增加异常点与报警事件的可视化。
4. 探索通过真实生产数据分析设备参数与废料发生之间的关系。
5. 根据实际需求开发实时监控界面。
